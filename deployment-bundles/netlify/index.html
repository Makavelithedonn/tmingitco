API Flow

      
    
        
  1. Request OTP: POST /api/request-otp with phone number. OTP generated, stored in KV (5 min TTL).
    2. 
        
  2. Verify OTP: POST /api/verify-otp with phone + OTP. OTP consumed from KV on success.
    3. 
        
  3. Create Card: POST /api/cards with card_id, name, phone. Phone hashed via HMAC before storing in D1.
    4. 
        
  4. Get Card: GET /api/cards/{card_id}. Retrieves card from D1 (phone_hash not decoded for security).
    5. 
        
  5. Submit for review: POST /api/submit with phone, card_id, name — tracked in the submissions table and reviewed by admin.
    6. 
      

      
Security Features

      
    
        
  • Rate Limiting: 10 req/min for OTP, 20 for verify, 50 for card ops per IP.
    • 
        
  • Phone Privacy: Phone numbers stored as HMAC hashes (SHA-256) in D1.
    • 
        
  • OTP Expiry: 5 minutes via KV time-to-live (TTL).
    • 
        
  • SQL Injection Prevention: Parameterized queries for all D1 operations.
